# 04_データベース設計

本システムは完全オフライン運用のため、データはすべてローカルの SQLite（`sekisan.db`）に保存する。
20年以上の長期運用を前提とし、マスターの世代・物件ごとの独立性を DB 構造で担保する。

## 1. マスターの二層構造（大元 ↔ 物件専用）

| 区分 | 意味 | 判別 |
| --- | --- | --- |
| 積算管理基本マスター（大元） | 全物件共通の雛形 | `project_id IS NULL` |
| 工事専用基本マスター（物件専用） | 物件ごとに切り離されたコピー | `project_id = <物件ID>` |

対象マスター（工種科目・明細・単位・材種区分・集計分類・型枠分類・部位・仕上明細セット等）は
共通して次の3列を持つ。

```sql
project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,  -- NULL=大元
source_id  INTEGER,                                            -- コピー元のレコードID
updated_at TEXT NOT NULL
```

### 1.1 プロジェクト作成時のスナップショット化

新規プロジェクト作成時に、大元の基本マスター全件を **物理コピー** して
`project_id = 新物件ID`、`source_id = コピー元ID` のレコードとして登録する。
以後その物件のデータは大元を一切参照しない。

### 1.2 参照元の切り替え

計算書・積算入力・明細データは、必ず自物件の `project_id` を持つマスターを参照する。
これにより物件ごとに独立して名称変更・科目移動・追加ができる。

### 1.3 大元への同期（マスター同期機能）

物件専用マスターでの修正・追加を、明示的な操作でのみ大元へ反映する。

- 反映先は **大元の基本マスターのみ**。他物件の専用マスターは一切書き換えない。
- 1回の同期は単一トランザクションで実行し、途中失敗時は全件ロールバックする。
- 対応関係は `source_id` で判定する（`source_id` が NULL の行＝物件で新規追加された行は、大元へ新規登録）。

### 1.4 独立性の担保

大元マスターへの科目追加・単価修正・名称変更は、作成済みプロジェクトへ**一切影響しない**。
物件へ取り込みたい場合は、物件側から明示的に「大元から取り込み」を実行した時のみ反映する。

### 1.5 連動範囲

- 物件専用明細マスターの文字修正・科目移動 → 計算書・明細セットマスター（物件側）と連動する。
- 大元の基本マスターには連動しない（同期を実行した時のみ反映）。
- 内訳書へ転送した後は連動を切り、内訳書単独の設定とする。

### 1.6 明細マスターは一方通行（写し取り方式）

基本明細マスターは「呼び出して入力するためのもの」であり、呼び出した先とは連動しない。

- 仕上明細セット（`m_finish_assembly_items`）は明細マスターを参照せず、
  呼び出した時点の内容（科目・部位番号・明細番号・材種区分・部位名・名称・摘要・単位・備考・積算用表示）を
  **そのまま写し取って保持**する。写し取り元は `source_detail_id` に残すが追跡用であり連動はしない。
- 基本明細マスターを後から修正しても、既存のセットは変わらない。
- セット内で編集した明細はセット固有の別物であり、明細マスターへは反映されない。
- 連動するのは工事（物件）の中だけ（物件専用明細マスター → 計算書・物件セット）。

### 1.7 物件専用明細マスター（集計書兼用）の生成

集計をかけた時点で、その物件が実際に使っている明細だけで生成する。
数量0などで使わなかった明細は、科目の最後に「不要明細」としてまとめる。

### 1.8 削除の禁止

連動するマスター（仕上明細セット・物件専用明細マスター）は、誤操作防止のため画面から削除できない。

- 使われなくなったセット・明細は、計算書から参照されなくなることで一覧に出なくなる（物理削除しない）。
- セット内の構成明細は、**最低1明細が残る範囲**でのみ削除できる。
- 例外は統合のみ。修正の結果まったく同じ内容のセットができた場合、確認のうえ1つへ統合する
  （参照している計算書は残す側へ付け替える）。

### 1.9 材種区分

数量チェック用の区分（仕上だけ／下地1だけ／軸組だけ、といった抜き出しに使う）。

- 基本マスター `m_material_categories` で番号・名称を管理し、番号入力で名称へ変換する（入力補助）。
- マスターに無い文字も入力でき、**入力してある文字を優先**する（明細側はテキストで保持する）。
- 後からマスターの名称を変えても、登録済みの明細・セットの文字は変わらない（連動しない）。

## 2. 工種科目の変更と明細の連動

明細は科目の「番号」「名称」ではなく **科目の内部ID（`subject_id`）** で紐づく。

- 科目の並び順変更・番号の振り直し・行挿入 → 明細はその科目に付いたまま移動する。
- 科目の改名 → 既存明細は改名した科目に付いたまま。同名で新規作成した科目は空になる。

## 3. 並び順（共通ソートキー）

並び替えルールは `src/core/sort/detailSortKey.ts` の1モジュールに集約し、
明細マスター・物件専用マスター・明細セットマスター・集計処理から共通で呼び出す。

優先順位（VBAのソートキー方式を踏襲）:

1. 工種科目
2. 部位Ⅰ（常に区分する）
3. 部位Ⅱの入力順（仕分け指示がある場合のみ）
4. 部位Ⅱ名（同上）
5. 部位番号（数値順）
6. 明細番号（数値順）
7. 部位文字
8. 名称文字（下段）
9. 単位（**単位マスターの番号順**）
10. 摘要（下段）
11. 摘要（上段）
12. 備考（下段）
13. 備考（上段）
14. 材種区分（番号順）
15. 元の並び順（安定ソート用）

- 明細番号に重複防止は設けない（同じ番号で異なる名称・摘要の明細を登録できる）。
- 文字項目は日本語の照合順（`Intl.Collator('ja')`）で比較する。
  漢字は「読み」ではなく照合順で並ぶため、読み順が必要な項目は将来「読みがな」列を追加して対応する。
- 未設定の数値は末尾に置く。

## 4. 内訳書（転送後）

内訳書は物件専用かつ**どこにも連動しない**設定を持つ。

- 工種科目の並び替え・名称修正（内訳書提出用）
- 表現変更（名称欄の半角表示、摘要内の `*`→`×`、単位 `㎡`→`m2` など）
- 書式変更（2段1明細 → 1段1明細）

## 5. 明細マスターの `[✔]面` `[✔]下`（基本マスターのみ）

- 明細ごとに 面/下 の有効フラグ、表示文字（既定「面」「下」）、区切り文字、並び順を保持する。
- 積算入力時、積算用表示に値がある場合のみ摘要欄下段の入力値の後ろへ半角スペースを空けて転記する。
  - 1明細目: 「（当明細の積算用表示）＋面」
  - 2明細目以降: 「（上明細の積算用表示）＋下」＋区切り＋「（下明細の積算用表示）＋面」
- 積算入力後は、変換済みの文字列として物件専用マスターに登録する（フラグは持ち越さない）。
